**Reviewed:** 2026-10-14

## 1. Audit → improve → dated proof

Real ops taught a loop the Lab now uses on itself:

1. **Audit** — Look at the live surface (site, queue, scorecard, inbox). Name what is true today.  
2. **Improve** — Fix the dumb requirement first; delete costume work; simplify; speed up; automate last.  
3. **Dated proof** — Put the result on `/live/` or in a dated doc. If it is not dated, it is a story, not evidence.

Never “improve” by inventing scale. Never leave an audit open as an eternal email watch when the human has closed the dump.

## 2. Kept informed is a scorecard dial, not a vibe

Customers (and free-plan clients) remember whether they got a real update — not whether the team *felt* busy.

Lab scorecard language:

| Habit | Lab move |
| --- | --- |
| Kept informed | Project notes + contact follow-up; say what shipped and what is blocked |
| Finish the job | Intake → Scope → Build → Proof → Deliver → Follow-up; owner + dated proof required |
| Name the KPI | When something is “off,” say which dial (honesty, cadence, usefulness) — not a vague “performance” fog |
| Facts over paraphrase | Prefer exports, dated pages, and screenshots of *our* surfaces over remembered vibes |

## 3. One operating system shape (steal structure, write our words)

Durable shops run something like:

**Purpose → playbook → people language → scorecard → learning loop → job aids**

That shape is installed at Lab scale in Lab OS. Sister offers share purpose + scorecard language; each still has one job. No fake mega-corp nav. No republishing third-party manuals.
